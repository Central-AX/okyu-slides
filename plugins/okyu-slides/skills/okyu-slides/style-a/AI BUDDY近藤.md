# AI BUDDY近藤 ─ ATISセミナー型スライドの作り方

作成：近藤 活（2026-09-28）
対象：ATIS AIセミナー（2026-10-05・四日市）の投影資料。Canvaに落とした版（100枚超）のデザインを、誰が作っても同じ水準で再現するための手順書です。

配布物は2つです。**同じフォルダに並べて置く**。
- `AI BUDDY近藤.md`（このファイル）
- `AI BUDDY近藤_素材/`（zipを展開したもの）

| 中身 | 用途 |
|---|---|
| `見本/` | Canva版から切り出した完成ページ16枚。**見た目の正解はこの画像** |
| `template.html` | このデザインの基本CSSと、8種類のページのひな形（グラフ2種を含む）。コピーして書き換える |
| `プロンプト/` | 近藤が実際にイラスト生成に使ったプロンプト（業務イラストの型／たとえ図の街／横長の伴走イラスト） |
| `assets/` | 飾り画像（右下の実と葉 `corner_bottom.png`） |
| `html2pptx.py` | HTMLを、文字を直せるPPTXに変換する（Canvaに取り込む用） |
| `audit_slides.py` | 「AIっぽさ」を数える自動チェック |

## Claude Code へ（最初に読むこと）

「ATISセミナーの型で」「AI BUDDYの型で」「このデザインで」と頼まれたら、このファイルの手順で作る。

1. **最初に `見本/` の16枚を全部見る**。見た目の正解はこの画像。文章の説明より画像を優先する。**ただし見本に写っている花（見出しの左・章扉の右下）は使わない**
2. **`template.html` をコピーして作る**（グラフも ⑦⑧ から）。CSSを一から書かない。値（色・寸法・文字サイズ）を変えない。部品を増やさない
3. 全ページ作る前に**2〜3枚だけ作り、画像にして依頼者に見せる**。赤が入ったら直してから残りを作る
4. 納品前に `audit_slides.py` と「11. 仕上げチェックリスト」を通す。通っていないものを「できました」と言わない
5. 迷ったら、このファイルの**上に書いてあるほうを優先**する。特に「2. 脱AIっぽさ」は、どの見た目の指定よりも優先する

必要なもの：`python3` と `pip install playwright python-pptx lxml pillow`、`playwright install chromium`。

## 1. このデザインの正体

- 元はATISのデザイナー佐藤さんが作った11枚の型。その最終ページの「使っている部品と値」を画素単位で実測して書き起こし、100枚まで広げた
- 見た目の特徴は4つ
  1. **紺の外枠（20px）**＋枠の内側に紺の帯が食い込む飾り（全ページ同じ位置）
  2. **左上＝紺の見出し＋紺の下線**、右下＝赤い実と緑の葉。**花は使わない**（見本には花が写っているが、それは真似しない）
  3. **紺・黒・グレー・赤の4色だけ**。赤は「成功側」「大事な数字」にしか使わない
  4. **大きい数字と短い一文**。1ページ1メッセージ

## 2. 脱「AIっぽさ」4ルール（最優先）

「文字サイズやレイアウト、カードスタイルの多さ、視認性の悪さから、AIぽさが抜けない」という指摘から作ったルール。**AIっぽさの原因は色やフォントではなく、箱の多さと実物の無さ**。凝った装飾（浮いたカード・巨大な飾り番号）ほどAIっぽく見える。

| ルール | 中身 | 数値目標 |
|---|---|---|
| ① 箱を使わない（最重要） | 影付き角丸の白カードをやめる。**薄い塗り面・罫線・見出し＋下線＋テキストの直接配置**で組む。比較は「2つの塗り面」で足りる | 枠で囲った箱は**1枚に1個まで**。3個以上なら設計からやり直す |
| ② 実画像を入れる | 写真・実画面のスクショ・ロゴ・出典の実物・生成イラスト | デッキ全体で**10枚以上** |
| ③ 文字を大きく | 本文は思っているより大きく | **18px未満は禁止**。1ページに**60px以上の主張を必ず1つ** |
| ④ 余白を意図して使う | 空白を放置しない。大きな文字・塗り面・罫線で枠取りする。項目が少ないページは縦に均等に並べる | ─ |

参考：直す前の39枚を数えたら、箱96個（1枚2.5個）／実画像0枚／18px未満の文字があるページ34枚／最大文字60px未満のページ14枚だった。

## 4. 文字

- **和文は Noto Sans JP の1種類**（Regular / Bold）。欧文の番号（01・02）は Elms Sans。入っていなければ Helvetica Neue で代用する
- **太字は `font-weight:700` で持たせる**。フォント名に太さを入れない（PPTXにしたとき太字の設定が消えて細字に化ける）

| 役割 | サイズ |
|---|---|
| 章扉の番号 | 220px |
| 章タイトル | 76〜96px・太字 |
| 大きい数字 | 123px（3つ並べるときは96px）・単位は44px |
| 主張の一文 | 60px・太字・紺 |
| 見出し（左上） | 40px・太字・紺 |
| 締めの一文（ページ下の1行） | 34〜40px・太字・紺 |
| 小見出し | 30〜32px・太字 |
| 本文 | **26px**（元の型は22px。投影で「見にくい」と言われて上げた） |
| 補足 | 22〜24px・グレー |
| 出典 | 16〜18px |

- 1ページの文字量は「見出し＋主張1つ＋補足1〜2行」まで

## 6. 図・たとえ図

- **「1枚で完結するたとえ図」を意図して置く**。家のたとえ図（基幹システム＝完成した家を買う／AIが使える＝自分で建てられるようになる）のページは、会場で写真を撮る人が一番多かった
- 図の文字は画像に焼き込まず、**上に重ねたテキスト**にする（あとから直せるように）
- 同じ形の図が2枚続くときは、**色で区別する**（例：失敗側は紺のまま、成功側だけ赤の濃淡2段）。形まで変えると別の話に見える。判断は必ず**2枚を並べて**行う

## 7. イラスト（画像生成）

- **絵は手描きのSVGではなく画像生成で作る**（gpt-image-2 系）
- **画風は1つに固定**：アイソメ（斜め上から見た立体）／濃紺の均一な輪郭／白・淡い青灰・中間の青・濃紺の4段階／**赤は画面に1か所だけ**／目鼻のない人物／薄い青灰のタイル板が宙に浮く。新しい絵を作るときは `見本/p065` `見本/p069` を「画風の正」としてプロンプトで指定する
- **主役を先に決めてプロンプトに書く**。街の絵は1回目、建物が主役で「大きな建設現場」に見えて不採用。直しは①人の身長を3.8倍 ②1人に1軒 ③全員が道具を持って手を動かす ④屋根の色を1軒ずつ変えて「別々の持ち主」を見せる。**監督・指差し・眺めているだけの人は、プロンプトで明示的に禁止する**
- 色を許すと、生成側が勝手に木目・陰影・茶色の輪郭を足してくる。「木材も含め全ての輪郭は濃紺／木目・ハッチング・陰影なし／フラットな面」と書く
- 周りが実画面のパートに、1枚だけ抽象アイコンを置くと浮く。**周りの素材と同じ種類で揃える**
- 横長2:1以上の絵は、固定サイズのモデルでは出ない（最大1.5:1）。横長に出せるモデルを選ぶ
- 候補は3〜4案を**1枚の比較画像**にまとめて見せる。青の濃さがずれた案は、既存の絵と同じページに並べない


### 近藤はこうやって作っていた（あなたの環境で使える手段を選んでよい）

- **エンジン**：OpenAI の画像生成（gpt-image-2）を主に使った。APIキーは自分の `.env` に置き、Claude Code から MCP サーバー経由で呼んだ。MCPが落ちた日は、同じAPIを叩く小さな Node スクリプト（プロンプトのファイル・出力先・サイズ・品質を渡す）で代用した。横長2:1以上は、横長サイズを出せる新しいモデル（gpt-image-2.5 系）で 2048×928 を直接出した
- 補助に Gemini 系の画像生成（MCP）も使った。既存画像の編集・キャラクターの一貫性・特殊な縦横比に強い。ただし**出力がJPEGになる**ので、透過PNGが要るスライド差し込みには向かない
- **1枚あたりの費用は数十円**（gpt-image-2 で $0.2〜0.3 程度）。クレジットが切れると `credit_balance_exhausted` で止まるので、大量に作る前に残高を見る
- **流れ**：①主役と画風をプロンプトに書く（`プロンプト/` の型をそのまま使い、情景の1文だけ変える）②生成 ③自分で講評して、ずれていたら1回だけ作り直す ④3〜4案を比較画像にしてユーザーに選んでもらう。**量産しない**
- **業務の小さなイラスト**（見本 p037 の各業務の横の絵）＝`プロンプト/業務イラスト_型.md`。1024×1024・品質 medium・画像内に文字なし。生成後に白い余白を切り抜いて使った
- **たとえ図**（見本 p065 家・p069 街）＝`プロンプト/たとえ図_街_採用版.txt`。アイソメの画風の書き方（輪郭の色と太さ、4色の塗り、赤は1か所、3Dレンダーにしない、人の大きさ）が全部入っている。新しいたとえ図はこれを土台に SUBJECT を書き換える
- 採用した画像は、プロンプト・エンジンと一緒に保存しておいた（あとで同じ画風で作り直せるように）
- 画像生成の手段がない環境なら、先にユーザーに「どのAPIキーで生成するか」を1回だけ聞く。手描きのSVGで代用しない

## 7-2. グラフ（template.html ⑦⑧）

近藤のやり方：**形はSVG、文字は上に重ねたHTML**。グラフ用のライブラリは使っていない。

- 円・棒・線などの形は `<svg>` で描く。数字やラベルは `<div class="figtxt">` を絶対位置で上に重ねる
- `html2pptx.py` はSVGを画像として貼り、`.figtxt` は**Canvaで直せる文字**として入れる（撮影中は `.figtxt` を隠すので、文字が画像に焼き込まれない）
- 色の使い分けはページと同じ：これまで＝グレー `#dedede`／AIで・助成側＝紺 `#003383`／自己負担・大事な数字＝赤 `#e43c59`
- ドーナツ：紺の円の `stroke-dasharray` の1つ目＝円周（2×3.14×半径）×割合。`transform="rotate(-90 …)"` で12時から始める（SVGの中なので PPTX の制約に当たらない）
- 横棒：棒の幅＝値÷最大値×最大幅。数字は棒の右端に置く。**最大幅は、一番長い棒の数字が右の枠からはみ出さない長さ**にする（`audit_slides.py` のはみ出しチェックで分かる）
- グラフの下に締めの一文と60px以上の数字を置く（「合わせて、ひと月75時間減ります。」）。出典か「※ 目安」を必ず添える
- 目盛り線・凡例の箱・3Dグラフは使わない。凡例は出典の行に文字で書く（「グレー＝これまで、紺＝AIで」）

## 8. 実画面・ダミー画面・伏せ字

- **ダミー画面は「ダミーだと分かった時点で失格」**。手描きっぽい線や「サンプル」バッジはすぐバレる
  1. まず実物を探す（Drive・Notion・freee の実ファイル）。列の構成・見出し・結合セル・合計行をそのまま写し、**氏名・時刻・金額だけ架空に差し替える**
  2. 実物が無ければ、実際のアプリで本当に作る（Googleスプレッドシートを作る、Gmailに下書きを作る）。取引先名は「サンプル商事」のように架空にする
- 実演は「画が変わること」が肝。スプレッドシートの画面ばかりだと変わり映えしない。例：請求予定の表 → 発行済みになる → 請求書PDFそのもの → Gmailの下書きに4通溜まっている。**「たくさん溜まっている」を見せるなら1通では足りない**
- 相手が実際に使っているツール名を確認する（ATISの勤怠は「ジョブカン」だった）
- **伏せる範囲**
  - 必ず隠す：社名／住所／電話・FAX／銀行口座／インボイス登録番号／財務数値
  - 隠さない：伝票番号／各行の金額／合計金額（デモの主役。良かれと思って隠さない）
- 受信トレイや下書き一覧には実案件が写る。撮ったあとに該当行を塗りつぶす。**画像の中の個人情報はプログラムでは見つからない。最後は必ず目で見る**
- 実画面のスクショは、自動で同期・共有されるフォルダに置かない

## 9. 数字と言葉

- **事例ページに必ず入れる3点**：①時間（月◯時間 → 月◯時間）②金額（時給2,000円換算で月◯万円）③作るのにかかった日数（赤いピル「制作3日」）
- **決めゼリフはデッキ全体で1回だけ**。4ページで違う金額の決めゼリフを出したら、聞き手がどれが本当の数字か追えなくなった
- 誠実さのための一言（「AIの間違いを人がチェックする仕事は残る」）は毎回添えてよい
- **出典のない数字を大きく出さない**。数字の意味は原文で確認する（「60%」が回収額ではなく再試行の成功率だった例がある）
- 事例の出典は、ロゴと記事・公式資料の実画面ごと貼る（該当箇所に赤枠）
- 補足の小さい文字や見出しを勝手に足さない。英字の飾り見出し（小さい英語ラベル）は使わない

## 10. Canva への受け渡し

```
python3 html2pptx.py deck.html -o out/ファイル名.pptx
```
→ できたPPTXをCanvaに取り込む。表紙以外の文字は全部Canva上で直せる。

- HTMLを書くときの制約（外すとPPTXで崩れる）
  1. `clip-path` は右向き矢印にしか使わない（変換側が「clip-path＝矢印」と解釈する）
  2. 角丸はピル（`border-radius:999px`）だけ
  3. グラデーション・影・変形（`transform`）は使わない
  4. 1行に収めたい文字は、要素の幅に余裕を持たせる
  5. 巨大な数字は字間を詰めず（`letter-spacing:0`）幅を明示する。詰めると折り返す
  6. テキストと画像を同じ要素に入れない（テキストが落ちる）
  7. 画像は枠と同じ縦横比に先に切っておく
- Canvaの癖
  - 半透明が不透明になる → 暗い幕は写真に焼き込む、薄い文字は色を混ぜて作る
  - 文字の箱の高さは行間で決まる
  - **Claude経由でCanvaの文字を置き換えると、文字の箱が3.4倍に膨らんで崩れる** → 文言の修正はCanva上で人が手でやる。並べ替えは自動でできる。ページの削除は自動ではできない
  - 非表示ページもPDF書き出しに混ざることがある。ページ番号は**相手が手元で見ている書き出しPDFの番号**で言う
  - Downloadsにある最新のPDFが最新版とは限らない。必要ならCanvaから書き出し直す
- 検証：`soffice --headless --convert-to pdf` でPDFにし、画像にして目で見る

## 11. 自動チェックと仕上げチェックリスト

```
python3 audit_slides.py deck.html
```
各スライド（`<section class="slide">`）ごとに、箱の数／18px未満の文字／最大の文字サイズ／横3・4分割／枠からのはみ出しを数え、OK か NG を出す。実画像の合計も出る。数字が通っても、**最後は画像にして目で見る**。

- [ ] `template.html` の値（色・寸法・文字）を変えていない。部品を増やしていない。花を入れていない
- [ ] `audit_slides.py` が全ページ OK（実演動画だけのページなど、例外は理由つき）／実画像がデッキ全体で10枚以上
- [ ] 各ページに60px以上の主張が1つある。締めの一文がある
- [ ] 決めゼリフはデッキで1回だけ。数字には全部出典がある
- [ ] イラストの画風が揃っている（濃紺の輪郭・4段階の青・赤は1か所）
- [ ] ダミー画面がダミーに見えない。伏せ字の範囲どおり（隠しすぎていない）
- [ ] 画像の中に実在の社名・口座・個人名が写っていない（目で見た）
- [ ] 表紙以外の文字がPPTX／Canvaで直せる
- [ ] 見本の16枚と並べて、見劣りしない

## 12. やってしまった失敗（同じことをしない）

| 失敗 | 次からこうする |
|---|---|
| テキストの説明だけで全ページ作り、何周も作り直した | 見本を見てから作り、2〜3枚だけ先に見せて赤を入れてもらう |
| カードを並べた「AIっぽい」デッキを出した | 箱は1枚1個まで。塗り面と罫線で組む |
| 色を塗り替えただけの3案を、対になるページと並べずに出した | 方向の違う案を、比較相手と並べて出す |
| Downloadsの最新PDFを「最新版」と思い込んだ | Canvaから書き出し直して確かめる |
| 素材を集めて報告し、スライドに入れなかった | 入れた状態で見せる |
| 抽象アイコンの1枚が、実画面が並ぶパートで浮いた | 周りの素材の種類に揃える |
| 「一部だけ伏せてある＝伏せ漏れ」と思い、意図して残した金額を隠した | まず伏せる方針を確認する |
| 顧客情報入りのスクショが、自動同期で共有の場所に上がった | スクショ置き場は最初から同期の対象外にする |
| 聞く前に論点を3つ出したら、全部すでにCanvaで直されていた | 質問する前に現物を見る |
